# Ответы к лабораторной работе 4

## Назначение функций

`MapGet()` регистрирует обработчик HTTP GET-запроса для указанного маршрута. В работе используется для получения списка знаменитостей, поиска по id, фамилии и получения пути к фотографии.

`MapPost()` регистрирует обработчик HTTP POST-запроса. В работе используется для добавления новой записи `Celebrity` из JSON-тела запроса.

`MapPut()` регистрирует обработчик HTTP PUT-запроса. В работе используется для полного обновления записи по id.

`MapDelete()` регистрирует обработчик HTTP DELETE-запроса. В работе используется для удаления записи по id.

`MapFallback()` можно использовать как общий обработчик запросов, которые не подошли ни под один маршрут. В данной реализации аналогичную роль выполняет `MapMethods("/{**path}", ...)`, возвращая сообщение `path ... not supported`.

`UseExceptionHandler()` подключает централизованную обработку исключений. Если обработчик маршрута выбрасывает исключение, управление передается на `/Celebrities/Error`, где формируется ответ с нужным статусом.

`UseStaticFiles()` разрешает отдавать статические файлы. В работе через него фотографии из папки `Celebrities` доступны по маршруту `/Photo/...`.

## Назначение объектов и интерфейсов

`IRepository` задает контракт DAL: получение, добавление, удаление, обновление и сохранение данных. Приложение работает с интерфейсом, а не с конкретной реализацией.

`Repository` реализует паттерн Repository и скрывает детали чтения и записи JSON-файла `Celebrities.json`.

`Celebrity` описывает одну запись данных: `Id`, `Firstname`, `Surname`, `PhotoPath`.

`IResult` представляет HTTP-ответ Minimal API. Через него можно вернуть JSON, 404, 400, 500, redirect и другие варианты ответа.

`Results` содержит фабричные методы для создания ответов: `Results.NotFound()`, `Results.BadRequest()`, `Results.Problem()`, `Results.Redirect()`.

`Results.Problem()` формирует ответ в формате Problem Details. В работе он используется для ошибок сохранения и добавления, где возвращаются поля `type`, `title`, `status`, `detail`, `instance`.

`Exception` является базовым классом исключений. Пользовательские исключения `FoundByIdException`, `SaveException`, `AddCelebrityException`, `DeleteCelebrityException`, `UpdateCelebrityException` позволяют отличать разные ошибки и назначать им разные HTTP-статусы.

`IDisposable` нужен для освобождения ресурсов. `Repository` реализует его, поэтому объект создается через `using`.

`HttpContext` содержит информацию о текущем HTTP-запросе и ответе. В обработчике ошибок через `context.Features.Get<IExceptionHandlerFeature>()` получается исключение, которое привело к ошибке.

`RFC 7231, section 6.6.1` описывает статус `500 Internal Server Error`, поэтому ссылка появляется в стандартном Problem Details-ответе для серверной ошибки.

## Обработка запросов и статусы

Успешные GET-запросы обрабатываются соответствующими `MapGet`-маршрутами и возвращают данные из `Repository`.

Если GET-запрос по id не находит запись, выбрасывается `FoundByIdException`, а `/Celebrities/Error` возвращает `404 Not Found`.

Успешный POST вызывает `addCelebrity()`, затем `SaveChanges()` и возвращает созданную запись.

Успешный DELETE вызывает `delCelebrityById()`, затем `SaveChanges()` и возвращает сообщение об удалении. Если id не найден, возвращается `404 Not Found`.

Успешный PUT вызывает `updCelebrityById()`, затем `SaveChanges()` и возвращает обновленную запись. Если id не найден, возвращается `404 Not Found`.

Неподдерживаемые маршруты обрабатываются общим маршрутом `MapMethods("/{**path}", ...)` и возвращают JSON с сообщением `path ... not supported`.

## Ada Lovelace и Charles Babbage

Ada Lovelace известна как автор первого опубликованного алгоритма, предназначенного для выполнения вычислительной машиной. Ее часто называют первым программистом.

Charles Babbage известен проектами Difference Engine и Analytical Engine. Analytical Engine считается одной из первых концепций универсального программируемого компьютера.
